You are a NEW Replit Agent working on the EXISTING Mudae Husbando V2 repository.

Your task is to add a SECURE, DEVELOPER-ONLY testing system that allows authorized developers to bypass normal gameplay restrictions while testing the bot.

This is development infrastructure.

==================================================
PRIMARY OBJECTIVE
==================================================

Add a developer-only command:

/developer

The command must provide a controlled development/testing mode.

When developer mode is enabled for an authorized developer, that developer may perform testing actions without being constrained by normal gameplay limits such as roll availability/cooldowns.

This exists specifically to make live Discord testing possible.

The developer system must NOT give these privileges to normal users.

==================================================
SECURITY REQUIREMENT
==================================================

Developer access MUST be based on an explicit Discord user ID allowlist.

Do NOT use:

- username
- display name
- nickname
- guild role
- administrator permission
- server ownership
- bot permissions

as the sole authorization mechanism.

The authoritative authorization value must be the Discord USER ID.

Use an environment variable / Replit Secret for the authorized developer IDs.

Recommended configuration:

DEVELOPER_USER_IDS

The value may contain one or more Discord user IDs.

Support a safe delimiter such as comma-separated IDs.

Example conceptually:

DEVELOPER_USER_IDS=123456789012345678,987654321098765432

Do NOT hardcode my Discord ID into source code.

Do NOT print the configured IDs into logs or Discord responses.

If the secret is missing, /developer must not grant access to anyone.

==================================================
DEVELOPER MODE SEMANTICS
==================================================

Developer mode should be explicitly toggled.

Recommended:

/developer

This command should display the developer controls.

Provide a clear status:

Developer Mode: OFF

or:

Developer Mode: ON

Allow the authorized developer to toggle it.

The state should be scoped to the developer who activated it.

Do NOT create a global "everyone is in developer mode" state.

Example:

Developer A → Developer Mode ON

Developer B → Developer Mode OFF

Normal User → no developer access

==================================================
DEVELOPER PRIVILEGES
==================================================

When developer mode is ON for an authorized developer, allow development/testing actions that are normally restricted.

At minimum:

### Unlimited /roll testing

The developer must be able to use:

/roll

without being blocked by normal roll availability/cooldown restrictions.

IMPORTANT:

This does NOT mean bypassing:

- verified-character filtering
- roll persistence
- claim logic
- ownership logic
- database transactions

Developer mode should bypass ONLY the gameplay restriction necessary to perform unlimited testing.

The roll must still be a real persistent roll.

The character must still come from the verified catalog.

The resulting roll must still be claimable normally.

==================================================
DO NOT BYPASS CLAIM RULES
==================================================

Developer mode MUST NOT automatically claim rolls.

Developer testing must still be able to test:

- public claiming
- another-user claiming
- first-claim-wins
- duplicate claim rejection
- expiration
- ownership

The developer roll should behave like a normal roll except for the specific roll-limit/cooldown restriction being bypassed.

==================================================

This is acceptable.

The developer can simply enable it again.

Do NOT store developer privileges as ordinary user data.

Do NOT add a "developer = true" field to mudae_users.

Developer status comes from the secure configuration.
