PHASE 2 — COLLECTION SYSTEM
==================================================

Harden /collection.

The existing collection query is based on:

mudae_collections
JOIN mudae_characters

and currently returns:

- character name
- series
- rarity
- value
- quantity
- favorite state

Preserve this underlying ownership model.

A collection row represents ONE UNIQUE CHARACTER.

quantity represents duplicate copies.

Example:

Character A ×1
Character B ×4

must remain two collection rows.

PHASE 3 — PROFILE
==================================================

Harden /profile.

The existing profile already displays:

- display name
- collection size
- claims
- rolls
- currency

The audit identifies an ambiguity:

What exactly does "collection size" mean?

Resolve this explicitly.

Recommended distinction:

Unique Characters
=
COUNT of distinct owned character rows

Total Copies
=
SUM(quantity)

Use clear labels.

For example:

Unique Characters: 27
Total Copies: 41

Do not call 41 "collection size" if it actually represents total copies.

If appropriate, profile may also display:

- total rolls
- successful claims
- unique characters
- total copies
- favorites
- wishlist count

Do not add speculative statistics that require unnecessary schema changes.

Prefer deriving statistics from existing data.
