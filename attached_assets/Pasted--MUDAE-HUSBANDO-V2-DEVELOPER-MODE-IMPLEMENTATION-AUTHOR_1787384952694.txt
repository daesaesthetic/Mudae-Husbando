==================================================
OBJECTIVE
==================================================

The current `/developer` command exists, but developer mode does not currently affect `/roll`.

The current implementation has:

- authorized developer IDs
- an in-memory enabled-developer set
- `/developer` toggle behavior

However, `/roll` currently has no normal availability/cooldown restriction for developer mode to bypass.

Therefore developer mode currently has no meaningful gameplay effect.

Correct this.

The goal is to provide an explicit development/testing mode that allows authorized developers to perform unlimited rolls and other supported developmental testing without normal roll restrictions.

==================================================
CORE BEHAVIOR
==================================================

Developer Mode must have two states for each authorized developer:

OFF

and:

ON

When OFF:

The developer behaves exactly like a normal user.

When ON:

The developer receives the intended development/testing privileges.

The mode must be explicitly toggled through:

`/developer`

==================================================
TOGGLE SEMANTICS
==================================================

The `/developer` command must behave as a real toggle.

First activation:

`/developer`

→ Developer Mode ON

Second activation:

`/developer`

→ Developer Mode OFF

The state must be deterministic.

The response must clearly tell the developer whether the mode is now:

ON

==================================================
CRITICAL REQUIREMENT — OFF MUST ACTUALLY TURN IT OFF
==================================================

This is the primary bug being addressed.

When developer mode is turned OFF:

ALL developer-mode privileges must immediately stop applying to that developer.

There must be no stale state where:

- `/developer` says OFF
- but `/roll` still behaves as developer mode

The implementation must make the ON/OFF state used by gameplay authoritative.

Do not maintain multiple independent developer-mode states.

There must be ONE authoritative state check.

==================================================
DEVELOPER ROLL BEHAVIOR
==================================================

When Developer Mode is ON:

The developer must be able to perform unlimited developmental `/roll` operations without normal roll restrictions.

This specifically means:

- no normal roll cooldown restriction
- no roll-count restriction
- no requirement to wait for normal roll availability
- repeated `/roll` calls must remain available for testing

The developer should be able to roll repeatedly during development/testing.

IMPORTANT:

Developer mode does NOT mean unrestricted ownership.

Developer mode does NOT automatically bypass character verification.

Developer mode does NOT automatically bypass global character uniqueness.

Developer mode does NOT allow developers to claim characters that are already globally owned.

Developer mode is primarily a TESTING / ROLL AVAILABILITY override.
